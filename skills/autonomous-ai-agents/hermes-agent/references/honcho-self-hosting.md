# Honcho self-hosting: prerequisites and privacy gate

Use when adding Honcho to Hermes, especially for private code/work conversations.

- Resolve the active profile from HERMES_HOME and inspect `hermes memory status`, `hermes plugins list --plain --no-bundled`, CLI help, and the local plugin catalog before installing. Honcho is a catalog plugin; do not assume it is bundled or that `hermes honcho` is already registered.
- Ask whether cloud export is authorized before enabling memory. Self-hosting the database alone does not establish no-cloud operation: Honcho defaults can use external text-generation AND embedding endpoints.
- Read the pinned catalog revision, its server config, plugin turn-sync, session-initialization and migration paths. Public docs may describe a newer revision; record which code was actually inspected.
- Treat model authorization separately from Honcho storage. Inspect `hermes proxy providers` and `hermes proxy status`, but do not treat that proxy's adapter list as proof that subscription-backed inference is impossible. For OpenAI, check current official Sign in with ChatGPT plan-usage support before falling back to weaker local generation or proposing a new paid API account; load references/honcho-openai-plan-usage.md. Existing Codex login, a separate app's OAuth grant and a paid API key are different authorizations.
- Check all deriver, summary, dream, dialectic-level, embedding and fallback model configs. For a local-only deployment, require local OpenAI-compatible inference with tool calling where needed; verify embeddings' dimension/input settings match the chosen model. Otherwise restrict egress to only the explicitly authorized model providers.
- Treat automatic memory migration as separate egress. In the inspected plugin, a new empty directory-based session may upload profile memories/MEMORY.md, USER.md and SOUL.md directly. Per-session skips that import, but reverify the current source. Do not activate the real profile merely to test connectivity.
- Distinguish normal turn redaction from confidentiality enforcement. Redaction of recognizable secrets does not classify corporate code or prove all PII is removed; inspect file-import paths separately.
- Inspect telemetry and tracing independently: CloudEvents, Sentry, Langfuse and full-payload exports. Set explicit disabled values/remove inherited tracing credentials. X-Honcho-Host and X-Honcho-Plugin headers go to the selected Honcho endpoint; verify an explicit local base URL rather than trusting SDK environment fallback.
- Inspect local dependencies before asking the user to install: Docker/Compose versus the manual PostgreSQL+pgvector path, uv/Python requirements, local inference, available RAM, and listening ports. Stock Compose may contain development database trust/sample credentials even when bound to loopback; do not copy unchanged for private data.
- Write downloaded audit evidence under the explicitly configured Hermes scratch directory. Do not trust TMPDIR blindly: on macOS it may resolve to the system temporary directory despite environment notes.
- Test synthetic ingestion, worker derivation and cross-session recall in an isolated workspace before attaching the live profile. Health checks alone do not establish usable memory. Observe/enforce service-specific network egress before claiming local-only data handling.
- Install/configure only after the deployment scope is authorized, use supported Hermes CLI settings, read back the exact effective target, and activate new tools/provider in a fresh session. Never claim installation or no-egress verification from static source inspection alone.

## Deployment lessons

- On macOS, a dedicated Colima profile can keep container host mounts restricted to the deployment directory. Use `--activate=false --ssh-config=false --ssh-agent=false` and an explicit mount; verify actual guest mounts. Never change the user's default Docker context to make a script work.
- Keep API, worker, PostgreSQL and Redis on an internal Docker network. Set container DNS explicitly to loopback so unknown names are not forwarded externally. Inspect effective port bindings: an internal-only network can discard configured publication. A narrow non-internal gateway can publish the authenticated API on host loopback while proxying only local model paths to host Ollama.
- Deny external model-gateway traffic with scoped VM firewall rules; allow only the local model endpoint. Give the gateway restart=no and apply its firewall before starting it after VM reboot. Prove the deny with a before/after canary, then repeat after a full dedicated-VM stop/start. Do not alter the macOS-wide firewall or unrelated VM chains.
- Run native Ollama under a dedicated launchd job with OLLAMA_NO_CLOUD=1 and a sandbox profile denying network-outbound except loopback. Verify inference still uses Metal, model APIs work, and direct external socket probes are denied. Keep bootstrap downloads separate from the sandboxed runtime; do not mistake a DNS error alone for proof of TCP denial.
- Prewarm tiktoken cl100k_base and o200k_base caches during image build and bake them into the read-only runtime image. Configure TIKTOKEN_CACHE_DIR explicitly. Frozen server workspace builds may need sibling SDK/CLI pyproject metadata copied before uv sync even when those packages are not installed.
- For nondefault embedding dimensions, run migrations first, then the upstream `scripts/configure_embeddings.py --yes` before API/worker startup. The startup validator intentionally refuses schema/config mismatches; never disable it or fabricate a larger embedding vector.
- An authenticated server still exposes webhook SSRF risk if hostname destinations are not resolved/checked. If webhooks are unused, deny their ingress routes, set MAX_WORKSPACE_LIMIT=0, leave the signing secret unset, verify the DB has no existing endpoints, and enforce worker egress denial. The limit does not delete old endpoints.
- The inspected self-hosted client intentionally replaces env-only API keys with the local placeholder. Store a real local JWT explicitly in the profile's Honcho host block, mode 0600; scope it to the workspace and keep the admin token separate. Do not reuse a cloud OAuth grant or print credentials.
- A CLI status can hide peer lookup failures, and plugin doctor may warn about a manifest hook even when lifecycle runs through MemoryProvider. Verify real authenticated HTTP requests plus provider initialization/tool schemas in a fresh runtime. `hermes --run-module unittest discover -s <test-dir> -p <test-file> -v` can exercise the actual installed runtime without making another model conversation.
- Use a separate synthetic workspace for memory acceptance. Read back ingested messages, wait for derived representation, then recall in a fresh client/session after API/worker and VM restart. Keep the real user workspace empty until activation; do not backfill old transcripts without authorization.
- Exercise an actual AIAgent.run_conversation finalizer, not only a manual SDK ingest or provider initialization. Exclude existing persona, built-in memory and project context from synthetic prompts. Preserve the activated profile's behavior while replacing only fixture identities, workspace and scoped fixture credentials in process memory; test both eager/tools and normal hybrid startup where applicable.
- Check completed turns during asynchronous initialization, FIFO write order, session rotation during initialization, core-dispatch backlog after rotation, pinned backend sessions, disabled/empty input and shutdown for every write cadence. The queued core session_id is the authoritative turn identity; reading the provider's mutable current session later can retag an earlier turn. An unavailable initialization must not silently discard an otherwise complete turn.
- Test the real startup service after stopping the dedicated VM. A starter that knows only the original Compose file can report healthy while leaving an added primary service stopped. Preserve the old database and model space, verify both intended endpoints, and repeat runtime egress probes after recovery.
- Test the user's actual languages before calling the memory pipeline reliable. Separate direct generation, embedding retrieval, stored-message fidelity, derived conclusions and fresh-session recall. Include negation, corrections, dates, identifiers, units, and mixed-language/code queries. Multilingual chat support does not imply multilingual embedding quality, and English smoke tests do not cover Russian memory.
- Inspect the embedding publisher's supported languages and task-prefix requirements. English-only embeddings may produce vectors of the correct dimension while failing semantic retrieval on Russian. Evaluate on paraphrases rather than exact-word matches; a small diagnostic failure is evidence of a problem, not a population accuracy estimate.
- Compare original text, derived representation and recalled answer when meaning drifts. A model can pass direct extraction yet fail the multi-stage memory chain, including translation of a negative constraint. Retaining raw messages prevents archival loss but does not make conclusions or search infallible. Do not silently swap embedding spaces: plan backup and re-indexing first.
- Before proposing a prompt fork or custom migration, inspect current official mechanisms and actual call paths in comparable systems. A language-preserving prompt definition or feature flag is not proof that the active public path enables it; distinguish merged features, unused branches, open PRs and operator reports.
- Honcho's older reasoning.custom_instructions is deriver-only. On versions with shared instructions, use workspace-level custom_instructions for the full chain and set peer_card instructions separately; module overrides replace shared text at that level, session values take priority, and empty strings suppress fallback. Verify the resolver and prompt call sites for the installed revision rather than relying on current-main documentation.
- Do not translate machine-readable peer-card entry-kind prefixes merely to keep fact bodies in Russian. Treat emergency English summary fallbacks and English-configured FTS separately from the language of stored factual content. Use existing source/evidence APIs for audits, remembering that evidence of what a model read is not proof that its answer relied on every item.
